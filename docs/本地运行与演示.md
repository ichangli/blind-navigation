# 本地运行与在线演示

仓库保存完整前后端源码。在线网站是同一仓库中的静态演示，不会运行 Python 或连接作者的数据库。

## 静态演示

运行 python tools/build_pages.py，再运行 python -m http.server 8777 --directory site-demo。以 HTTP 网址访问，不要直接双击 HTML；地图 Worker 和 JSON 资源需要静态服务器。

演示使用项目和版本独立的 IndexedDB/localStorage。上报、审核、图片和收藏仅存本机，同一浏览器中的两个页面可以共享。不同浏览器不会共享。重置只清除此项目；浏览器禁止存储或空间不足时，顶部提示仅本次会话。

三个路线案例由最终道路几何离线生成。网站只展示固定起终点，不提供任意地点的实时路径服务。地图采用 WGS84，手机演示地图与 Web 地图一致。

## 原版完整程序

Windows：安装 Python 3.10+，双击 run_demo.bat。原启动器使用本机 8000 端口和 SQLite，可自动建立演示数据。初始演示账号见 backend/README.md；只用于本机开发与演示，勿沿用到公网服务。

也可手动建立虚拟环境、安装 backend/requirements.txt、使用 uvicorn backend.main:app 启动。Linux/macOS 使用 .venv/bin/python 替代 Windows 的 .venv\Scripts\python。

完整地图服务配置填写 backend/.env，字段说明见 backend/.env.example 和 backend/.env.demo.example。数据库可选择 SQLite 或 PostgreSQL。原版地图中的建筑、道路、底图和无障碍路线服务需要自行发布或提供可访问的 GeoScene 地址。高德移动地图与检索需要对应类型的 Key。原版完整程序依赖这些配置；静态演示不需要。

SQLite 与上传内容属于运行数据，不纳入公开仓库；后端首次启动会创建表；仅 APP_ENV=demo 时初始化演示业务数据，具体逻辑保留在 backend/app/seed.py。演示模式重新启动可能补齐被删除的种子演示记录，这属于原版演示行为。

## GIS 再制作

_dev_archive/gis 和其测试完整保留。部分脚本使用 ArcPy，需要 ArcGIS Pro；网络数据集制作和原版网络分析还需要对应分析扩展。历史脚本中保留原工作目录默认值，重新制作前应将输入/输出路径改为本机对应位置。

已经整理的数据在 datasets 和 shenzhen_data 中，普通静态演示无需重新制作 GDB。tools/export_demo_data.py 用开源 Python 数据工具读取最终 GDB，导出 Pages 所需的设施、建筑语义、简化展示道路及路线案例；不会请求 GeoScene 或地图 API。

## 发布

GitHub Pages 的 Source 选择 GitHub Actions。工作流 .github/workflows/pages.yml 先调用 tools/build_pages.py，再仅上传 site-demo。仓库 README 的源码下载保留完整源文件和数据说明，不受 Pages 发布目录的影响。
