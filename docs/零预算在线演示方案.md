## 1. 采用的目标

用户已明确：同一个公开 GitHub 仓库托管完整作品源代码，供访问者下载；GitHub Pages 提供无需下载即可访问的在线演示。暂不投入预算，完整后端不要求在 Pages 运行。面向国内外访问者，首版地图和案例范围为深圳福田。

交付目标：一个可分享的 HTTPS 网址，能进入 Web 管理端和移动端演示，展示三维建筑、道路、水域、设施、事件、统计和路线案例，并完成本机范围的演示上报、审核和重置。

Pages 在线演示运行时不需要启动本机电脑、Python 后端、GeoScene Server、Portal 或 Data Store。不购买服务器、域名、数据库或收费 API；采用平台提供的 github.io 地址。完整源码继续保留前后端、本机启动方式和相关配置说明。

采用一个公开的完整项目仓库。完整前端、Python 后端、依赖声明、启动脚本、配置模板、必要的样例数据、GIS 数据处理工具和测试均纳入源码托管；GitHub Pages 仅部署其中 site-demo 目录的静态文件。

真实配置及口令、本机虚拟环境、运行数据库、真实用户上传内容和重复打包产物不提交。需要额外下载的数据在 README 中提供明确入口和版本说明；源代码 ZIP 不依赖个人电脑上的 D:/E: 路径才能定位资源。

## 2. 推荐结构

一个仓库提供两个入口：仓库首页的“下载完整源码”和“在线演示”。演示页同时提供“查看源码”链接。

建议保留现有源文件的相对布局，增加独立演示目录，不为部署而整体搬动后端和前端源文件：

    blind-navigation/
      backend/                 Python 后端与配置模板
      styles/                  原版前端样式
      data/                    配置及样例业务数据
      shenzhen_data/           必要数据及数据说明
      tools/ 或 _dev_archive/  仍有维护价值的数据处理工具
      tests/ 或原测试目录      相关测试
      docs/                    运行、数据和部署说明
      site-demo/               Pages 专用静态演示
      .github/workflows/       只上传 site-demo 的 Pages 工作流
      README.md
      .gitignore
      原版 HTML、JS 和启动脚本

发布工作流仅把 site-demo 上传为 Pages artifact，后端代码留在 GitHub 仓库供阅读、克隆和下载，不进入网站发布包。GitHub Actions 在这里承担静态文件发布任务。

源码复现说明应列出 Python 环境、依赖安装、数据库初始化、配置模板填写、数据路径以及地图服务或替代实现要求。原版完整运行仍需要其对应环境和服务；静态演示单独提供免配置入口。去除完整后端的 GeoScene 依赖属于后续改造，不能将其写成已完成能力。

依据：[GitHub Pages 发布源与自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

访问者浏览器 → GitHub Pages → HTML/CSS/JS、静态地图数据、样例业务数据、预设路线。

浏览器内增加显式演示数据适配层，供页面读取样例、修改演示状态。少量偏好使用 localStorage；演示记录和本机图片如需保留，使用 IndexedDB。

演示存储使用包含项目标识和数据版本的独立命名空间，不复用正式登录 token 或正式用户数据；样例文本和图片使用可公开的虚构或脱敏素材。同一个 github.io 主机下的不同项目共享浏览器 origin，重置只能删除本项目记录，不能清空整个站点存储。

IndexedDB 不可用、空间不足或私密模式限制时，提示无法持久保存，可降级为本次页面会话；图片 Blob 保存失败时也要反馈真实状态。

不在页面里继续请求一个不存在的后端，再等失败后切换 mock。进入演示时就明确选择演示数据源，页面始终显示“在线演示”。

适配范围包含各按钮内直接发出的 fetch 调用，例如事件详情、审核、删除、上报和路线规划，不能只替换首页的数据加载函数。

GitHub Pages 是静态托管平台，可以提供 HTML、CSS、JavaScript 和文件，不承担常驻 Python API。

依据：[GitHub Pages 官方介绍](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

## 3. 功能安排

| 模块 | 首版实现 | 访问者看到的边界 |
|---|---|---|
| 入口 | 项目说明、进入管理端演示、进入移动端演示 | 不要求注册或输入真实账号密码 |
| 三维地图 | 自有建筑 GeoJSON 拉伸、底图、水域、道路、设施 | 地图可实际旋转、缩放、点选；数据有版本和来源 |
| 事件与图表 | 固定样例事件、筛选、详情、统计联动 | 属于样例业务数据，不称为实时城市事件 |
| 上报与审核 | 使用样例照片或本机选图，演示分类、提交、审核、删除 | 修改仅存在当前浏览器，不发送到共享服务器 |
| 导航 | 3～5 个经过核对的固定起终点案例、路线对比、步骤播报 | 标注“预设路线演示”；首版不开放任意目的地搜索 |
| 设施接驳 | 从已有公交站、地铁口等数据展示附近设施 | 站点数据展示；到站提醒仍标注模拟 |
| 语音 | 优先使用设备语音播报；浏览器支持时可演示语音输入 | 不支持时保留文字输入，不承诺跨浏览器识别一致 |
| 天气与环境感知 | 移到演示区，标注样例；或从首版主流程隐藏 | 不把固定天气、固定感知结果当作实时结果 |
| 重置 | 一键恢复初始演示数据 | 清除当前浏览器的演示修改 |

跨端含义：同一浏览器、同一站点下的管理端和移动端可以共享演示数据；不同手机、不同浏览器之间不共享。若需要跨标签页即时更新，应使用 storage 事件或 BroadcastChannel，并在页面重新激活时刷新。

Pages 演示不提供真实用户账户、多人共享上报数据库、真实实时公交或真实环境识别服务。完整源码仍保留已有后端功能；将来部署完整线上系统时再接常驻 Python 后端及相应数据服务。

## 4. 地图处理

### Web 管理端

保留当前 ArcGIS JS 显示库和 SceneView，优先复用相机、白模、事件、设施、属性和语义交互。关闭 Portal/WebScene、SceneServer、MapServer、FeatureServer、NAServer 等 GeoScene 服务入口。

建筑使用现有 8,897 栋建筑文件；道路、水系和深蓝底图改用本地数据源。服务端 identify 改为浏览器拾取或本地空间查询。水波纹在本地面数据源上验证，效果不满足时先用静态水面，列为明确的视觉差异。

尽量同源提供 SDK、样式、Workers、字体、精灵、图标和图表依赖。锁定已验证的版本，先不同时升级主地图引擎。根据 SDK 分发条款处理依赖包，不调用收费底图或位置服务。

依据：[ArcGIS JS 本地资源说明](https://developers.arcgis.com/javascript/latest/working-with-assets/)、[SDK 下载及历史版本](https://developers.arcgis.com/javascript/latest/downloads/)。

### 移动端

原有移动地图依赖高德 JS Key 和后端配置。零预算首版建议增加轻量演示地图适配器，采用 Leaflet 稳定版本直接绘制同源 GeoJSON：道路、水域、设施、样例位置及路线。保留周边 UI 和交互流程。

无需加载外部公共地图瓦片；地图限定在福田演示范围，自有底图数据提供背景与注记。高德地址搜索和 Web 服务不作为上线前提。若以后使用已有免费额度，作为单独可关闭的增强项，核对账号配额后再接入。

依据：[Leaflet 1.x 官方教程](https://leafletjs.com/examples-v1.html)。

### 坐标

静态发布地图和路线统一为 WGS84，并实际重投影。已有高德来源案例和事件需检查 GCJ-02 转换，给数据写明 coordinateSystem；不沿用通过用户 ID 是否为空来猜坐标系的逻辑。

## 7. 验收标准

1. 新访客无需账号或密码，可进入 Web 和移动端演示。
2. 页面内清楚显示演示状态、样例路线和本机保存范围。
3. Web 三维地图缩放、旋转、图层、建筑点选、道路选择、设施筛选、事件定位正常；手机二维地图验收缩放、拖动、点选和路线显示，首版不承诺与 Web 相同的三维和旋转能力；已知视觉差异列入说明。
4. 浏览器不请求 127.0.0.1、旧 GeoScene 域名、后端 API，也没有必需的地图 Key。
5. 上报、审核、删除、统计和重置在同一浏览器闭环；另一个浏览器访问时出现独立初始数据。
6. 路线案例端点、图形、距离和提示经过核对，语音不可用时仍能阅读步骤。
7. Android Chrome、iPhone Safari 和桌面浏览器测试；定位、麦克风被拒绝时不阻断演示，不自动伪装成已获取真实位置。
8. 实际从中国大陆和至少一个海外网络测试页面、SDK、地图资源、样例流程。仅首页 HTTP 200 不算通过；无法实测的网络区域在验收记录标为未验证。
9. 记录首次加载和缓存后加载耗时、资源体积及手机交互情况，再决定是否拆包或生成切片。
10. 发布包和浏览器可见文件中没有 backend/.env、数据库口令、JWT 密钥、真实上传图片、用户个人资料及访问令牌。
11. 仓库 README 同时提供在线演示、下载/克隆完整源码、本地运行、数据准备和演示能力说明；实际在干净目录下载一次，按说明核对代码和依赖是否齐全。
12. 完整源码保留真实后端接口及启动方式；静态演示的本地数据适配器只在演示模式启用，不能覆盖或删除原业务实现。

GitHub Pages 提供访问入口，但不能承诺所有国内运营商和海外地区的速度一致；地图依赖自托管可以减少第三方资源的失败点，实际效果仍按第 8 项验收。

## 8. 可选第二阶段：浏览器内真实路线求解

如果希望零服务器费用下支持自由选点，可在静态演示稳定后评估此阶段：

- 在本地离线构建最终路网的稳定节点、边和空间索引，修复已知成本问题，导出紧凑图文件。
- 页面按需下载图，Web Worker 内进行 Dijkstra 或 A* 求解，处理边中吸附、临时分边、方向和桥隧层级。
- 同一区域的通行设置可参与边过滤或成本；现场设施未知与无法连通应明确返回，不从地图画线推断真实安全性。
- 在手机上测图文件体积、初始化内存、首次求解时间和连续求解，达标后才替换预设路线入口。

这一阶段仍可放 GitHub Pages，但需要额外开发与性能验证。它不提供多人共享事件库或跨设备持久数据，首版在线演示不以此为前置条件。

## 9. 费用与平台边界

| 项目 | 本方案安排 |
|---|---|
| 源码托管与下载 | 同一个公开 GitHub 仓库保存完整作品源码 |
| 网页托管 | GitHub Free + Pages，仅发布 site-demo 静态目录 |
| 网站地址 | 使用平台 github.io 地址 |
| 常驻后端和数据库 | 不部署 |
| 地图与路线 | 自有静态数据 + 预设路线，不购买 API |
| 本机演示存储 | 浏览器 localStorage / IndexedDB，无云存储账单 |
| 后续真实跨设备业务 | 暂不纳入零预算首版 |

按当前官方限制，Pages 发布站点不大于 1 GB，月带宽软限制为 100 GB。SDK、图片和地图资源仍需控制体积；需要大范围公开推广时重新评估配额。依据：[GitHub Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。

不以 GitHub Actions 常驻运行后端，不把 Codespaces 开发环境作为长期网站服务器，也不依赖有到期或休眠条件的免费数据库来保存访问者数据。

## 10. 当前结论

推荐采用“一个完整源码仓库 + 同仓库 Pages 静态演示”。访问者可以下载完整前后端源码，也可以直接通过演示网址查看地图、业务流程和案例；账户、共享存储、实时公交与环境感知的演示边界明确展示。后续再决定是否增加浏览器路线计算或常驻完整后台。

静态演示改造与发布已完成；浏览器自由选点求解等可选增强尚未实施。实机、WebGL 和国内外网络的验证范围以发布验证记录为准。
